# TAHOPE_data_process
本篇記錄為處理TAHOPE相關IOP/SOP時，有關地面測站、觀測資料(任意)的問題與細節，僅供參考，有可能有本人沒有遇過的問題。

## 地面測站
地面測站包含{date}.QPESUMS_STATION.15M的自動站資料，以及{date}.QPESUMS_STATION.10M的有人站資料，自動站分布較多且廣，但山區都比較少，如果想要使用到山區的測站資料，要斟酌使用。
由於有上面兩種資料，資料處理上有幾點需要注意：

1. 所有資料、變數名稱所顯示的**時間都是UTC**
2. 讀取時支援編碼為BIG5，用來支援繁體中文解碼。常見的utf-8在這邊無法使用。
3. 資料內變數名稱兩者差異不大，但是風向風速這類變數，在有人站是有瞬時跟平均兩個種類，所以變數的名稱不太一樣，其中下圖中的變數名稱分別在10M和15M是對應的

4. 如果你是在 ASRAD 上下載每小時資料的話，會有一些固定的 QC 數值：

- `-9991`：儀器故障待修  
- `-9996`：資料累計於後  
- `-9997`：因不明原因或故障而無資料  
- `-9998`：雨跡（Trace）  
- `-9999`：未觀測而無資料

5. 這邊程式僅使用簡單的QC，就是若有負值超過-99.0(為TAHOPE測站資料儲存格式無資料的類別)的變數就把那一個測站於該時間的資料全部改為NAN，QC資料的方式請以自己的需求去做更改

## 探空資料
探空資料在TAHOPE實驗中，除了氣象署原本就有的觀測站點，還有加放新竹、宇那國島的探空。探空資料儲存格式為.txt(或是經QC後的.csv資料)，處理資料時有以下幾點需要注意：

1. 如果點開資料夾，可以發現探空資料有不同類型的檔案，主要會使用到的是.edt和.fix這兩種，前者為經過基礎QC且包含所有高度的資料檔(連下墜過程也會記錄)，後者為固定高度資料檔(如500m, 1000m, 1500m)，由於僅記錄特定高度，所以資料密度較低。
2. 探空資料點密度會與平常在氣象署看到的密集很多，所以在計算一些熱力參數的時候可能會有些問題，例如在使用metpy相關套件，可能會出現高度點受到風吹影響，導致跳出error指示資料沒有按照由低到高排序。或是計算LFC、EL兩個交叉點時，因為早八探空的低層加熱尚未完全，導致在較低的高度上會出現抖動的溫度線，使得在低處氣塊降溫率就與環境降溫率出現交叉(EL)，導致該天CAPE的數值被低估。
3. 因此，對探空資料做簡單平滑，或是讀取時不要取這麼密集的資料點，只保留連續性的剖面特徵，都可以降低計算參數時遇到的error，或是無法計算CAPE的窘境。
